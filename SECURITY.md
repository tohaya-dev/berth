# Security Policy

This policy covers the Berth runtime as shipped in this repository: PostgreSQL with pgvector, Redis, two API and two worker pods on a single-node K3s cluster, installed with `deploy/k8s/linux/install-k3s.sh` and `ops/linux.sh`. The repository still contains older standalone code paths (SQLite/Chroma defaults in `cynovela.yaml`). The Kubernetes renderer overrides them, and they are not the deployment described here.

Never include credentials, generated passwords, keys, database dumps or private documents in a public issue.

## Trust boundary

- Berth is designed for a dedicated Linux or WSL2 host run by one operator. Anyone who can read `$BERTH_DATA_DIR`, use its kubeconfig, or run `kubectl exec` in the namespace can read all data, keys and passwords. Such people are inside the trust boundary.
- The web entry is a `kubectl port-forward` bound to `127.0.0.1:18765` by default. `BERTH_ENTRY_ADDRESS` can widen it. The forward does no source filtering and carries plain HTTP, so a widened entry needs a host firewall, and TLS through a reverse proxy.
- The K3s API server listens on `0.0.0.0:26443`. Protect this control-plane port with host and network controls.
- The application Service is `ClusterIP`. No Kubernetes NetworkPolicy is rendered.

## Secrets and keys

| Secret | Generated by | Stored |
|---|---|---|
| `admin_password`, `pg_password`, `secret_key` | `deploy/k8s/linux/render.py`, once, on first install | `$BERTH_DATA_DIR/secrets/` (mode 600); Kubernetes Secret `cynovela-secret`; `$BERTH_DATA_DIR/rendered/infrastructure.yaml` |
| PostgreSQL password in the pods | from the Secret | file mounted read-only at `/run/berth-secrets/pg_password`; the PostgreSQL container reads it through `secretKeyRef` |
| `secret_key` in the pods | from the Secret | environment variable `CYNOVELA_SECRET_KEY` |
| Initial administrator password | from the Secret | passed only to the bootstrap Job |
| Cluster kubeconfig | `install-k3s.sh` | `$BERTH_DATA_DIR/client.yaml`, `$BERTH_DATA_DIR/kubeconfig` (mode 600) |

Reinstalling reuses the existing secret files, and the bootstrap never changes an existing user. Keep `$BERTH_DATA_DIR`, rendered manifests and backups private. For production use, consider a secret manager and encrypted storage. `.containerignore` keeps `**/secret.key`, `store/models` and `_oss-rc-backups` out of the image build context. Build from a clean checkout anyway (see [Before distributing](docs/oss/before-distributing.md)).

## Defences in the shipped configuration

1. **Accounts.** Interactive sign-in requires a username and password; the former user-id-only login is refused. There are two roles, `admin` and `viewer`, plus workspace/collection access rules. A fresh install creates one administrator, `cynovela`, whose password is 32 random bytes (URL-safe) generated at install time. The bootstrap refuses a password shorter than 12 characters.
2. **Password hashing.** PBKDF2-HMAC-SHA256, 100,000 iterations, per-user random salt (`db.py`, `hash_password`).
3. **Login tokens.** HS256 JWTs, valid for 8 hours by default (configurable from 0.01 to 720 hours). The signing key is derived from `secret_key` by HMAC-SHA256, so all API replicas accept the same tokens without sharing the encryption key itself.
4. **API keys.** CLI and HTTP MCP keys (`cyn_…`) are stored only as SHA-256 hashes and can be revoked. A key can be limited to workspaces, collections and MCP tools. Administrative MCP write operations pass an explicit gate. The tool restriction and that gate apply only to MCP: on the REST API a key acts with its role, and its workspace/collection scope is enforced on chat, RAG query, streaming and chunk listing. Keys do not expire; revoke them when they are no longer needed.
5. **Encryption at rest (application level).** Document originals and the stored `openai_compat` provider token are encrypted with Fernet using `secret_key`. The masked copy of each document is stored in plain text.
6. **Masking.** During ingestion, personal data is detected with Presidio, spaCy and pattern rules, and a masked copy is stored next to the encrypted original. Detection is best-effort; see [Known limitations](docs/oss/limitations.md#masking-and-personal-data).
7. **Pod hardening.** API and worker pods run as the non-root uid/gid 10001 with `runAsNonRoot`, the `RuntimeDefault` seccomp profile, all capabilities dropped and no privilege escalation. They do not mount a Kubernetes service-account token. Models and ingest folders are mounted read-only.
8. **Outbound requests.** The LLM endpoint must be `http(s)`; link-local and cloud metadata addresses are refused. Image description through a remote vision endpoint is blocked unless explicitly enabled. Model files are never downloaded at runtime (`HF_HUB_OFFLINE=1`).
9. **Audit.** Authentication failures, user and workspace changes, publishing, backups, chat queries and PII detections are recorded in the audit log.

## Known weaknesses and operational guidance

| Area | Weakness | Guidance |
|---|---|---|
| Initial administrator | Not forced to change the generated password | Change it, or hand it over securely, before other people use the system |
| Password hashing | 100,000 PBKDF2 iterations is below current OWASP guidance (≥ 600,000 for PBKDF2-SHA256, or Argon2id) | Use long passwords; a future upgrade on next login is intended |
| Login rate limit | Login, token refresh, password change and password verification: 5 requests/minute per client address and API pod (SlowAPI); no limit on other endpoints. Behind `kubectl port-forward` all clients share one address | For any exposure beyond the local machine, front the service with a reverse proxy that enforces TLS and stricter limits |
| Database at rest | PostgreSQL files, including masked text, vectors, users and audit records, are not encrypted by Berth | Put `$BERTH_DATA_DIR` on encrypted storage |
| Backups | `pg_dump` output is not encrypted and is stored next to a copy of `secret_key` | Keep backups on protected, encrypted storage; never copy them to untrusted media |
| Key colocation | `secret_key` is on the same host as the data it protects | Protects against a stolen dump without its key, not against a host compromise |
| Container filesystem | `readOnlyRootFilesystem` is not set; the application writes runtime state to the container layer | Treat pods as disposable; do not add write-capable mounts |
| External LLM | Retrieved document text is sent to the provider you configure | Use a provider you trust with that data; prefer a local provider for sensitive corpora |
| Kubernetes API | Bound to `0.0.0.0:26443` | Firewall it; never reuse this cluster for untrusted workloads |
