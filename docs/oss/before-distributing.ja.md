# 配布・提供の前に

Berth を再配布する人(ソース、ビルドしたイメージ、モデルキャッシュのいずれでも)や、他の人のために運用する人向けのチェックリストです。Berth はソースのリリース候補として公開されています。**アプリケーションイメージは公開していない**ので、運用者がそれぞれ自分でイメージをビルドします。そのイメージを他の人に渡す人は、以下の義務を負います。

## 何を渡すのかを把握する

| 対象 | このリポジトリに含まれるか | 渡すときの義務 |
|---|---|---|
| Berth のソース | 含まれる | MIT。`LICENSE`、`NOTICE.md`、`THIRD_PARTY_NOTICES.md` を残す |
| 同梱のブラウザー用ライブラリ(Chart.js とそのプラグイン、marked) | 含まれる | MIT。ライセンス本文は [`docs/oss/licenses/`](licenses/) にある |
| アプリケーションイメージ | 含まれない(自分でビルドする) | Debian パッケージ、Python パッケージ(たとえば LGPL-3.0 の psycopg。[`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md) と [`dependency-licenses.csv`](dependency-licenses.csv) を参照)、下の spaCy モデルを含む |
| spaCy `en_core_web_sm` 3.8.0 | イメージ内(ビルド時に pip の wheel で導入) | MIT |
| spaCy `ja_core_news_sm` 3.8.0 | イメージ内(ビルド時に pip の wheel で導入) | モデルデータは **CC BY-SA 4.0**(UD Japanese GSD に由来)。帰属表示と継承(share-alike)の条件を守る |
| BAAI/bge-m3 | 含まれない(利用者がダウンロード) | MIT。ファイルを再配布する場合は著作権表示と許諾表示を添える |
| BAAI/bge-reranker-v2-m3 | 含まれない(利用者がダウンロード) | Apache-2.0。ファイルを再配布する場合はライセンス本文と、あれば NOTICE を添える |
| 回答生成用の LLM | 含まれない(同梱は一切しない) | 各プロバイダーの条件に従う |

**モデル。** Berth はモデルの重みを同梱しません。利用者それぞれが `tools/download-rag-models.py` を実行し、Hugging Face から固定リビジョンを取得して、全ファイルの SHA256 を検証します([モデルポリシー](model-policy.ja.md))。オフライン環境向けなどでモデルキャッシュを自分で配る場合は、上のライセンス本文を一緒に添えてください。`locks/models.json` による検証が通るよう、固定リビジョンのまま配ってください。他の人が稼働させている環境からモデルキャッシュをコピーしてはいけません。

**イメージの脆弱性。** リリース候補イメージの監査では、ChromaDB のアドバイザリーを含む未解決の指摘がまだ残っています([`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md))。機能テストが通ったことだけを理由に、問題なしとしてイメージを公開しないでください。自分でビルドしたイメージをスキャンし、指摘を精査してください。

## 配布物に秘密情報を入れない

秘密情報は、`ops/linux.sh install` が初めてマニフェストをレンダリングするときに、インストールごとに生成されます。他のインストールの秘密情報をコピーして使ってはいけません。

| 秘密情報 | 置き場所 |
|---|---|
| `admin_password`、`pg_password`、`secret_key` | `$BERTH_DATA_DIR/secrets/`(モード 600) |
| Kubernetes Secret `cynovela-secret` | クラスター内と、`$BERTH_DATA_DIR/rendered/infrastructure.yaml` の `stringData`(平文) |
| Pod 内の PostgreSQL パスワード | `/run/berth-secrets/pg_password` に読み取り専用でマウント |
| Pod 内の `secret_key` | Secret から渡される環境変数 `CYNOVELA_SECRET_KEY`。保存された文書の原文と API トークンの暗号化に使われ、ログイントークンの署名鍵もここから導出される |
| クラスター管理者の kubeconfig | `$BERTH_DATA_DIR/client.yaml` と `$BERTH_DATA_DIR/kubeconfig`(モード 600) |
| バックアップ | `PG_BACKUP_DIR` 内の `pgdump-*.dump` と `secret.key-*` |

チェックリスト:

- [ ] `$BERTH_DATA_DIR` やバックアップ用のディレクトリを、パッケージに入れたり、同期したり、共有したりしない。バックアップには暗号化されていない SQL ダンプと、保存文書を復号できる鍵が一緒に入っています。
- [ ] イメージはクリーンなチェックアウトからビルドする。ビルドは `.containerignore` の除外対象を除いて、リポジトリのディレクトリをまるごとイメージにコピーします。除外されるのは `store/models`、`**/secret.key`、`_oss-rc-backups`、`.venv-oss`、`.env` などです。`.venv` ディレクトリ、`berth-amd64.tar` のような保存済みイメージのアーカイブ、ツリー内の別の場所に置いたダンプは**除外されません**。アーカイブやバックアップはリポジトリの外に保存してください。
- [ ] 生成されたパスワード、`secret_key`、スコープ付き API キーを、Issue、ログ、コミットに貼らない。
- [ ] 公開するものに秘密情報や個人のパスが含まれていないかスキャンする。このソースリリースの作成に使ったスキャナーは開発用ツリーにあり、このリポジトリには含まれていません。好きな秘密情報スキャナーを使ってください。確認すべきものは、秘密鍵、GitHub トークン、OpenAI 形式や `cyn_` 形式の API キー、AWS キー、JWT の文字列、`secret.key*`、`*.dump`、データベースファイルです。

## アカウントと初期パスワード

- [ ] 新規インストールでは管理者 `cynovela` が 1 人だけ作られ、ランダムなパスワードが `$BERTH_DATA_DIR/secrets/admin_password` に置かれます。初回ログイン時の変更は強制されません。他の人が使い始める前に変更するか、安全な経路で引き渡してください。
- [ ] 利用者ごとに個人のアカウントを作り、必要最小限のロールを与える(管理をしない人は `viewer`)。インストール後にユーザー一覧を確認し、自分で作っていないアカウントはアクセスを取り消してください。
- [ ] CLI や MCP との連携には、管理者パスワードを共有せず、スコープ付き API キーを発行する。
- [ ] 再インストールしても既存のユーザーと鍵は残ります。ブートストラップが既存のパスワードを変えることはありません。

## ネットワークへの公開

- [ ] Web の入口は既定で `127.0.0.1:18765` にバインドします。`BERTH_ENTRY_ADDRESS` で公開範囲を広げる場合は、ホストのファイアウォールでポートを制限してください。port-forward は接続元を絞らず、通信は平文の HTTP です。
- [ ] K3s の API サーバーは `0.0.0.0:26443` で待ち受けます。ホストとネットワークの両面で保護し、信頼できないネットワークに公開しないでください。
- [ ] ログインとほかのパスワード関連エンドポイントの制限は接続元アドレスごとに毎分 5 リクエストで、`kubectl port-forward` の背後では全クライアントが同じアドレスになります。ローカルマシンの外から使わせる場合は、TLS とより厳しい制限をかけるリバースプロキシを前段に置いてください。
- [ ] 外部の LLM プロバイダーに接続すると、検索で取り出した文書テキストがそこへ送られます。どのプロバイダーにデータが渡るのかを利用者に伝えてください。

## 同梱データ

サンプルの文書群やデータベースは同梱していません。リポジトリには、開発時の試験で使った小さなフィクスチャファイルが 4 つあります。これらは `$BERTH_DATA_DIR/ingest` にコピーされず、自分でそこに置かない限り索引には入りません。

| ファイル | 内容 |
|---|---|
| `demo_data/d.txt`、`demo_data/p25/d.txt` | 短い日本語の製品説明サンプル(約 1.2 KB と約 0.6 KB) |
| `ingest/test_pii_ingest.md` | 日本語のマスキング試験用文書。氏名、電話番号、メールアドレス(`example.co.jp`)、番号はすべて架空で、架空であることが明記されている |
| `ingest/sub1/nested.txt` | フォルダーの再帰取り込みを試す 1 行の日本語テキスト(仮の氏名を含む) |

他の人に環境を渡す前に、`$BERTH_DATA_DIR/ingest` には利用者が読んでよい文書だけが入っていることを確かめてください。ワークスペースやコレクションのアクセス規則は、各利用者が検索できる範囲を制限します。ただし、何を取り込むかを選ぶことの代わりにはなりません。

## 利用者に伝えること

- [ ] データがどこにあり、どうバックアップされるかを伝える([よくある質問](faq.ja.md#データはどこにありますか))。
